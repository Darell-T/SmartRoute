# Complete the lint cleanup

Use this plan to remove the remaining Ruff, ESLint, Oxlint, and runtime
quality debt without changing SmartRoute behavior. Execute one numbered batch
at a time. Stop after every batch and update `docs/lint-cleanup-handoff.md`.
Do not begin the next batch automatically.

Review every completed batch with `docs/lint-cleanup-review-spec.md`. The
worker must not approve its own work.

This procedure intentionally stays in one 500 to 800 line document. Every
batch depends on the same inventory, sequencing rules, and final gate. Splitting
the procedure would create duplicated instructions and allow the batch records
to drift apart.

## Required execution loop

Use this sequence inside every batch:

1. Regenerate the JSON inventories with the checked-in configurations.
2. Save the exact owned file list and per-rule counts in the handoff.
3. Read every owned production file, its callers, and its focused tests.
4. Record behavior that must not change.
5. Add or strengthen characterization tests before a risky refactor.
6. Repair one cohesive cluster of findings.
7. Run the smallest focused tests after that cluster.
8. Run the complete owned test set after the file is green.
9. Run the complete affected subsystem suite after the batch is green.
10. Run the scoped linter, type checker when applicable, and fresh quality gate.
11. Inspect the diff for behavior changes, metric gaming, disabled rules, dead
    code, copied contracts, and unnecessary files.
12. Regenerate all three inventories and record the exact reduction.
13. Stop. Do not select or start the next batch.

Do not use `--skip-tests` as batch certification. It is only a local diagnostic
for coverage that was already generated by the same source tree.

## Non-negotiable repair rules

- Do not edit `pyproject.toml`, `frontend/eslint.config.mjs`, or
  `frontend/.oxlintrc.json` to reduce counts.
- Do not add broad `noqa`, `eslint-disable`, `@ts-ignore`, `@ts-nocheck`, or
  formatter exclusions.
- Do not increase a value in `quality/baseline.json`.
- Remove a baseline entry only after a fresh quality run proves that the entry
  is stale. Inspect that one-entry diff before accepting it.
- Do not lower complexity by adding pass-through wrappers, one-use services,
  boolean out-parameters, or files that have no independent responsibility.
- Do not split a cohesive file only because it is large. A split must create an
  independently understandable responsibility.
- Do not replace a typed contract with `Any`, `unknown`, an unsafe dictionary,
  a chained assertion, or a non-null assertion.
- A `SAFETY:` comment is allowed only after code checks the invariant at
  runtime and TypeScript cannot express the result. The comment must identify
  the exact check and why the assertion follows.
- Preserve official GTFS and GeoJSON field names at provider boundaries.
  Rename vague internal symbols such as `shape`, `data`, `item`, or `obj` to
  the domain value they hold. If the anti-slop rule flags an exact provider
  field incorrectly, add a narrow rule test before repairing the plugin.
- Preserve skip count, assertion meaning, async ordering, and mock call
  assertions. Follow `docs/test-suite-rationalization.md` when exact duplicate
  coverage exists. Never remove a test to make a metric pass.
- Keep provider fallbacks explicit. Missing live data must never become
  fabricated certainty.
- Keep one backend-owned canonical itinerary. Frontend cleanup must not add
  duration, ranking, transfer, dwell, or recommendation arithmetic.

Before closing a batch, inspect these patterns in the owned diff:

```powershell
rg -n "noqa|eslint-disable|@ts-(ignore|nocheck)|as unknown as|SAFETY:" <owned paths>
git diff --check
git diff -- pyproject.toml frontend/eslint.config.mjs frontend/.oxlintrc.json quality/baseline.json
```
